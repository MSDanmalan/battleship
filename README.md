# Battleship Game

A browser-based implementation of the classic Battleship game, built with JavaScript as part of [The Odin Project](https://www.theodinproject.com/) curriculum.

The project focuses on modular JavaScript, Test-Driven Development (TDD), object-oriented programming, and separation of application logic from DOM manipulation.

## Features

- 10 × 10 game boards for both the player and computer.
- Ships are placed using preset positions. Game logic validates placements to prevent invalid or overlapping ships.
- Turn-based gameplay against a computer opponent.
- Computer opponent selects random, previously untried coordinates.
- Attack handling with visual feedback for hits and misses.
- Ships track received hits and automatically detect when they are sunk.
- Automatic game-over detection and winner announcement.
- Responsive board layout for smaller screens.
- Modular architecture separating game logic, game control, and DOM manipulation.

## Technologies

- **JavaScript (ES6 Modules)** – Application logic.
- **HTML5** – Page structure.
- **CSS3** – Styling and responsive layout.
- **Jest** – Unit testing.
- **Webpack** – Module bundling and development server.
- **Babel** – JavaScript transpilation.

## Getting Started

### Prerequisites

- Node.js
- npm

### Installation

1. Clone the repository:

   ```bash
   git clone https://github.com/MSDanmalan/battleship.git
   ```

2. Navigate into the project directory:

   ```bash
   cd battleship
   ```

3. Install dependencies:

   ```bash
   npm install
   ```

### Development server

Start the local development server:

```bash
npm start
```

Open the local URL displayed in your terminal.

To rebuild the development bundle when files change:

```bash
npm run watch
```

### Tests

Run the complete Jest test suite:

```bash
npm test
```

### Production build

Generate an optimized production build:

```bash
npm run build
```

The generated files are placed in the `dist/` directory.

## Deployment

The GitHub Actions workflow in `.github/workflows/deploy.yml` runs on pushes to `main` or when manually started. It installs dependencies, runs the Jest suite, builds the production site, and publishes the contents of `dist/` to GitHub Pages.

In the repository's GitHub Pages settings, set the publishing source to **GitHub Actions**. Build output is generated by the workflow and does not need to be committed.

## How to Play

1. Start a new game using the **Start Game** button.
2. Select a square on the computer's board by clicking it or navigating with the arrow keys and pressing **Enter** or **Space**.
3. The game displays whether your attack was a hit or a miss.
4. The computer automatically takes its turn after a valid player attack.
5. Continue attacking until one fleet has been completely destroyed.
6. The game announces the winner when all ships belonging to either player have been sunk.

## Project Structure

The application separates its responsibilities into modules:

- `src/ship.js` – Ship creation, hit tracking, and sunk-state management.
- `src/gameboard.js` – Board creation, ship placement validation, and attack handling.
- `src/player.js` – Player behavior and computer attack selection.
- `src/gameController.js` – Turn management and game-over detection.
- `src/game.js` – Game object and initial game setup.
- `src/dom.js` – DOM rendering and user interaction.
- `src/index.js` – Application entry point.
- `src/index.html` – HTML page template.
- `src/style.css` – Page styling and responsive layout.
- `src/tests/` – Jest tests for the game logic and DOM interactions.
- `.github/workflows/deploy.yml` – GitHub Pages build and deployment workflow.

## Testing

The project uses Jest for unit tests and DOM interaction tests.

Tests cover:

- Ship creation, hit tracking, and sunk-state management.
- Gameboard creation and ship placement validation.
- Attack handling, including repeated and invalid attacks.
- Player behavior and computer attack selection.
- Game controller turn management.
- Victory detection and game-over conditions.
